# 專案生命週期管理

整合專案初始化、開工、收工的工作流程。

## 觸發時機

- 「開新專案」
- 「收工」
- 「繼續工作」
- 「初始化專案」
- 「建立專案工作模式」

## 三大流程

### 1. 初始化專案（init-project）

當使用者說「開新專案」、「新建專案」、「我想做一個 XXX 工具」時觸發。

**固定檔案：**
- `AGENTS.md`：長期穩定規則與 SOP
- `<專案名>工作筆言.md`：持續追加的進度、決策、驗證、待辦及踩坑
- `.gitignore`：排除憑證、代理設定、快取

**Obsidian 路徑：**
```
~/我的雲端硬碟/2ndBrain/InitialProject/<專案名>工作筆言.md
```

### 2. 收工（shutdown）

當使用者說「收工」、「結束了」、「準備換電腦」時觸發。

**核心原則：**
- **追加，不覆蓋**：工作筆言只追加新內容，保留歷史
- **三方同步**：本機 → Obsidian → GitHub

### 3. 繼續工作（resume）

當使用者說「開工」、「繼續」、「接續工作」時觸發。

**核心原則：**
- **只讀取，不修改**：開工流程只讀取狀態，不做同步或寫入
- **恢復現場**：快速摘要進度，詢問下一步

## 工作筆言格式

```markdown
# {專案名} 工作筆言

> 📌 持續追加的進度、決策、驗證、待辦及踩坑。每次收工時更新，不覆蓋歷史。

## 上次做到哪

**最後動作**：初始化專案
**完成檔案**：AGENTS.md、.gitignore
**對話脈絡**：剛建立專案，還沒有實質進度
```

## AGENTS.md 格式

```markdown
# {專案名}

## 專案目的

（描述這個工具做什麼）

## 工作狀態

- 進度：0%（剛初始化）
- 開始日期：{今天}
- GitHub：https://github.com/jarvis800317/{專案名}

## 工作節奏

| 觸發語句 | 執行動作 |
|---------|---------|
| 「開工」 | 讀取工作筆言、檢查 Git 狀態、輸出摘要 |
| 「收工」 | 盤點、寫入工作筆言、同步 Obsidian、commit + push |
| 「繼續」 | 讀取工作進度繼續工作 |

## 安全規則

- 安裝任何外部套件、skill、MCP 前，先做 Security Scan
- 對外訊息先出草稿，不直接送出
- 不可把 API Key、token、憑證檔提交到版本庫
```

## 觸發語句對照表

| 使用者說 | 執行動作 |
|----------|----------|
| 「開新專案」 | 執行 init-project 流程 |
| 「收工」 | 執行收工同步 |
| 「繼續」 | 執行開工流程 |
| 「開工」 | 執行開工流程 |
| 「初始化專案」 | 執行 init-project 流程 |

## 不該做的事

- ❌ 在未確認的情況下覆蓋既有專案
- ❌ commit `.codex/`、`.claude/`、`node_modules/`、`.env`
- ❌ 初始化完成後未建立工作筆言
- ❌ 收工時覆蓋工作筆言（應追加）
- ❌ 開工時執行同步或寫入
