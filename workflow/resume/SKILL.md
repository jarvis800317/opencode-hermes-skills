# 繼續工作技能

接續先前工作，快速恢復現場。依據「專案初始化開工與收工通案標準」執行。

## 觸發語句

- 「開工」
- 「繼續」
- 「接續工作」
- 「上次做到哪」
- 「我們繼續」
- 「接下來呢」

## 固定檔案

每個專案必備：
- `AGENTS.md`
- `<專案資料夾名稱>工作筆記.md`
- `.gitignore`

Obsidian 路徑：
```
~/我的雲端硬碟/2ndBrain/InitialProject/<專案資料夾名稱>工作筆記.md
```

## 開工 SOP

本流程只做讀取與狀態確認，不修改檔案、不同步、不提交。

### 步驟 1：確認專案

從對話脈絡推斷專案名稱，預設路徑：
- 本機：`~/我的雲端硬碟/Jarvis專案/projects/<專案名>/`
- Obsidian：`~/我的雲端硬碟/2ndBrain/InitialProject/<專案名>工作筆記.md`

若無法確認，詢問：「請告訴我專案名稱。」

### 步驟 2：讀取工作筆記

依序檢查：
1. `~/我的雲端硬碟/2ndBrain/InitialProject/<專案名>工作筆記.md`
2. `~/我的雲端硬碟/Jarvis專案/projects/<專案名>/<專案名>工作筆言.md`

若都找不到，回應：「找不到『{專案名}』的工作筆言。可能是新專案，請問要繼續哪個專案？」

### 步驟 3：檢查 Git 狀態

```bash
cd ~/我的雲端硬碟/Jarvis專案/projects/<專案名>
git status -sb
git remote -v
git branch -vv
```

需要確認遠端可見性時使用：
```bash
git ls-remote --heads origin
```

### 步驟 4：輸出開工摘要

從工作筆言中提取：
- `上次做到哪`：最後動作、已完成檔案
- `最近更動紀錄`：最近 3-5 筆記錄
- `踩坑筆言`：待注意的事項

用口語化方式回應，範例：

```
📋 專案：quality-plan-generator
上次做到：完成第五章「施工品質管理」，已部署至 GitHub Pages
目前進度：83%（5/6 章）
待確認：主任技師對第八章「矫正與預防措施」的審查意見

🕳️ 待注意：座標系統用 (-5,5)，與地圖資料不同，需做轉換

📍 建議下一步：回覆主任技師審查意見並修訂第八章
```

### 步驟 5：輸出結構化摘要

### 步驟 6：等待使用者選擇方向

「請問要繼續做什麼？」

**本流程不做：**
- ❌ `git pull`、commit、push
- ❌ 筆言寫入
- ❌ 套件安裝
- ❌ 外部同步

## 特殊情況

| 情況 | 回應 |
|------|------|
| 無工作筆言 | 「這是乾淨的開始，請告訴我你要做什麼工具或任務。」 |
| 專案已完成的 | 「這個專案已完成。上次做到：{結案狀態}。要開新專案嗎？」 |
| 多日未繼續 | 「距離上次已 {N} 天。工作筆言顯示：{摘要}。要繼續嗎？」 |

## 不該做的事

- ❌ 未讀工作筆言就假設進度
- ❌ 自行發起需要長時間運行的工作，應先確認意圖
- ❌ 在「開工」流程中執行同步、commit 或寫入
